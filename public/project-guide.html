Одно изменение — один источник

Как обновлять лекции и заметки, сохранять свои правки и выпускать согласованную версию курса без параллельных копий.

public/course.json, public/assessment.json, public/teacher-pack.json, authoring/questions.json и reports/registry.json — результаты генерации. Не исправляйте их отдельно: следующая генерация заменит ручные изменения.

Старые app, components, hooks, lib оставлены для истории миграции. Их редактирование не меняет действующие лекции. dist — сборка для просмотра.

2. Общий сценарий и личные заметки

Общий сценарий собирается вместе с курсом в public/teacher-pack.json и доступен посетителям сайта. В окне преподавателя поверх него применяются личные правки этого браузера; в окно аудитории сценарий не загружается.

Перед обновлением версии экспортируйте личные заметки из панели занятия. Новая версия использует отдельное хранилище: старые правки автоматически не накладываются на изменившиеся слайды. Не меняйте номер версии в экспорте ради обхода проверки. Сопоставьте заметки по ID и перенесите только проверенные изменения.

Для постоянной индивидуальной поправки выполните npm run generate:content -- --teacher. В private/teacher-source.json найдите запись нужного ID; перенесите только её в объект slides файла authoring/teacher-overrides.json и измените поле note. Запись содержит contentHash и поля сценария, подготовки, конспекта, вопросов, ответа и времени. В репозитории хранится только поправка, а не второй полный сценарий.

При изменении слайда генератор остановится, если хеш индивидуальной заметки устарел. Сохраните поправку во временный файл, уберите её из teacher-overrides.json, сгенерируйте новую опорную запись с --teacher, затем верните согласованный текст с новым хешем и повторите генерацию. Не заменяйте хеш без содержательной проверки. Файлы private — вспомогательный экспорт; генератор не читает их как авторский источник. При изменении общего шаблона отдельно пересмотрите индивидуальные поправки: они имеют приоритет.

Сохранение в браузере не обновляет Git и сайт у других пользователей. Экспорт редактора — предложение изменений: перенесите его в авторские источники, затем пересоберите весь комплект.

3. Рабочий цикл

  1. Посмотрите git status. Экспортируйте браузерные черновики и личные заметки, если они есть.
  2. Найдите тему и ID слайда. Сформулируйте изменение: ошибка в определении, условии примера, задании или сценарии.
  3. Измените соответствующий источник. Проверьте связанные критерии и варианты ответов. Сохраняйте ID при текстовых правках.
  4. При изменении выпуска обновите contentVersion в генераторе. Версия курса, банка ответов и сценария создаётся из одного значения.
  5. Запустите npm run generate:content. Команда обновляет весь комплект; ручное копирование пакета не требуется.
  6. Просмотрите git diff: исходная правка и зависимые изменения должны объяснять друг друга. Повторная генерация без правок должна давать тот же результат.

4. Когда повтор нужен, а когда мешает

Определение объясняет признак понятия. Пример показывает применение. Сравнение помогает отличить ошибку. Конспект закрепляет короткую запись. Самопроверка требует самостоятельного ответа. Полный разбор исходных данных проводится один раз в конце вопроса. Схема показывает структуру решения: связи объектов, ветви условий, расчёт или время. Не превращайте абзацы соседних слайдов в карточки схемы. Повторные слайды механизма и ошибки удалены; их смысл сохранён в сравнении и заметках.

Не переносите весь разбор в каждую заметку. Записывайте, что преподаватель делает на этом слайде: что спросить, где выдержать паузу и по какому признаку оценить ответ. Объяснение, реплика преподавателя и эталон ответа выполняют разные задачи.

Повтор темы между лекциями допустим при новой задаче: трассировка сначала вводится, затем применяется к изменению и ревизии модели. Термины «операция», «обязательность» и «открытый вопрос» встречаются в разных контекстах; указывайте контекст, не объединяйте определения механически.

Один ID требования сохраняет смысл во всём кейсе: REQ-14 — запрет отгрузки карантина, REQ-27 — история статуса. Учебные альтернативы A/B в разных вопросах могут иметь разные условия; перед сравнением назовите исходные данные.

Длительность заметок — оценка полного прохождения материала, а не обещание уложиться в пару. Планируйте встречи по четырём вопросам темы и сохраняйте объяснение перед заданием. РПД и официальные часы не подтверждены.

5. Проверка и просмотр перед выпуском

npm run check:generated
npm run check:methodology
npm run audit:content
npm run check:readiness -- --strict --teacher=public/teacher-pack.json
npm run test:notes
npm run lint
npm run build
npm run check:privacy
npm run preview -- --port 4176

Откройте локальный курс. Проверьте изменённую лекцию: определение, пример, четыре задания, заметки и окно аудитории. Посмотрите длинные тексты на узком экране. При работающем preview выполните:

node scripts/check-startup-notes.mjs
npm run test:smoke

npm run audit:content проверяет действующий курс. Старый scripts/audit-content.mjs относится к архиву миграции. Машинные проверки находят структурные ошибки и полные повторы, но не подтверждают правильность всех предметных утверждений.

После согласования предпросмотра проверьте состав коммита. В него входят источники и согласованные результаты генерации; личные экспорты и временные файлы остаются локально. Пуш в main запускает публикацию Pages. В текущей задаче сначала требуется утверждение пользователя, затем пуш.
