Одно изменение — один источник

Как обновлять лекции и заметки, сохранять свои правки и выпускать согласованную версию курса без параллельных копий.

public/course.json, public/assessment.json, public/teacher-pack.json, public/laboratories.json, authoring/questions.json и reports/registry.json — результаты генерации. Не исправляйте их отдельно: следующая генерация заменит ручные изменения.

Старые app, components, hooks, lib оставлены для истории миграции. Их редактирование не меняет действующие лекции. dist — сборка для просмотра.

Расширение движка vendor/olgakraven-lecture-engine-0.2.0-course.5.tgz снимает старое ограничение на 4 пары и 5 вариантов. Его источник — сохранённый архив 0.2.0 и scripts/prepare-engine.mjs. Интерфейсные адаптеры проверяют совместимость при сборке.

2. Общий сценарий и заметки

Сценарий генерируется вместе с курсом в public/teacher-pack.json. Панель преподавателя загружает его автоматически и показывает версию над заметками. Сценарий должен позволять начинающему преподавателю провести тему: назвать исходные знания, объяснить причину решения, разобрать шаги и ошибки, задать вопрос и проверить ответ.

Можно читать разделы, менять размер текста, сохранять личные правки заметок и импортировать или экспортировать совместимый пакет. Сохранения прежних версий не удаляются и не перекрывают текущий опубликованный сценарий. Для переноса старых правок сначала сравните их с новыми условиями и примерами.

Для изменения общей заметки используйте authoring/teacher-overrides.json с ID и хешем текущего слайда. Веб-редактор и вход в него удалены. Исходники меняют в проекте, затем выполняют генерацию и проверки.

3. Рабочий цикл

  1. Посмотрите git status. Сохраните заметки из панели преподавателя, если они есть.
  2. Найдите тему и ID слайда. Сформулируйте изменение: ошибка в определении, условии примера, задании или сценарии.
  3. Измените соответствующий источник. Проверьте связанные критерии и варианты ответов. Сохраняйте ID при текстовых правках.
  4. При изменении выпуска обновите contentVersion в генераторе. Версия курса, банка ответов и сценария создаётся из одного значения.
  5. Запустите npm run generate:content. Команда обновляет весь комплект; ручное копирование пакета не требуется.
  6. Просмотрите git diff: исходная правка и зависимые изменения должны объяснять друг друга. Повторная генерация без правок должна давать тот же результат.

4. Сохраняйте объяснение при удалении повторов

Вопрос включает смысл и границы понятий, пошаговый пример, выбор действия, объяснение механизма, исходные данные полного случая, схему решения, проверку изменённого условия и самостоятельные задания. Эти этапы выполняют разные учебные задачи. Объединяйте одинаковый пересказ, сохраняя причины и шаги, которые опытный преподаватель может восполнить самостоятельно, а начинающий должен увидеть в материале.

Схема показывает связи объектов, ветви условий, расчёт или время. Заметка объясняет, как пройти эти связи, что спросить и по какому признаку оценить ответ. Дополнительный случай должен менять исходные данные и требовать переноса способа решения.

Лаборатория должна позволять менять параметры и наблюдать результат: состав артефакта, движение, отказ, расчёт или переход состояния. Добавьте процедуру, исходный и отрицательный наборы, границу, анимацию и сравнение запусков. Отдельно проверьте вход через видимую кнопку и большой режим лаборатории.

Повтор темы между лекциями допустим при новой задаче: трассировка сначала вводится, затем применяется к изменению и ревизии модели. Термины «операция», «обязательность» и «открытый вопрос» встречаются в разных контекстах; указывайте контекст, не объединяйте определения механически.

Один ID требования сохраняет смысл во всём кейсе: REQ-14 — запрет отгрузки карантина, REQ-27 — история статуса. Учебные альтернативы A/B в разных вопросах могут иметь разные условия; перед сравнением назовите исходные данные.

Длительность заметок — оценка полного прохождения материала, а не обещание уложиться в пару. Планируйте встречи по четырём вопросам темы и сохраняйте объяснение перед заданием. РПД и официальные часы не подтверждены.

5. Проверка и просмотр перед выпуском

npm run check:generated
npm run check:methodology
npm run audit:content
npm run check:readiness -- --strict --teacher=public/teacher-pack.json
npm run test:notes
npm run lint
npm run build
npm run check:privacy
npm run preview -- --port 4176

Откройте локальный курс. Проверьте изменённую лекцию: определение, пример, четыре задания, заметки и окно аудитории. Посмотрите длинные тексты на узком экране. При работающем preview выполните:

node scripts/check-startup-notes.mjs
npm run test:interactions
npm run test:smoke

npm run test:interactions проверяет расширенные блоки, все 26 лабораторий на широком и мобильном экране, 208 разборов выбора, текущие заметки и синхронизацию соответствий и анимации. npm run audit:content проверяет действующий курс. Старый scripts/audit-content.mjs относится к архиву миграции. Машинные проверки находят структурные ошибки и полные повторы, но не подтверждают правильность всех предметных утверждений.

После согласования предпросмотра проверьте состав коммита. В него входят источники и согласованные результаты генерации; личные экспорты и временные файлы остаются локально. Пуш в main запускает публикацию Pages. В текущей задаче сначала требуется утверждение пользователя, затем пуш.
